## GitHub 镜像与双推

- 用户提供镜像仓库 `https://github.com/BingJian-REMIX/Basalt-VD`。该仓库原为独立 `Initial commit`（`9a18f0c`，仅 3 行 README），与本地 11-commit 历史无关，普通 push 必然 non-fast-forward。
- 经确认采用「完整镜像覆盖 + 双推」：`git push --force-with-lease github main` 覆盖 GitHub 初始提交，CNB 快进；两端 `main` 与本地逐 hash 一致。
- README 顶部补 GitHub 镜像地址，第 12 节改为双推约定。
- remote 结构：`origin` 保留 CNB fetch，`github` 为独立 remote；`origin` 的 pushurl 显式列出 CNB + GitHub 两个地址。**坑**：添加第一个 pushurl 后 Git 不再用 fetch url 推送，必须显式把 CNB 也加进 pushurl 列表，否则双推只剩 GitHub。

## 环境要点（长期有效）

- 本机到 GitHub 的 TLS 经 `127.0.0.1` 代理 MITM，git/curl 报 `CRYPT_E_NO_REVOCATION_CHECK (0x80092012)` / `unable to get local issuer certificate`。git 用一次性 `-c http.sslVerify=false`，curl 用 `--ssl-no-revoke`；不写入 config。
- GitHub PAT 对 **Git over HTTPS 必须用 Basic `x-access-token:<PAT>`**；`Authorization: Bearer <PAT>` 会让 git 回落并报 `could not read Username`。Bearer 只对 REST API 有效。
- 双推时两平台凭据不同，用按主机配置：`-c "http.https://cnb.cool/.extraheader=Authorization: Basic <cnb>"` 与 `-c "http.https://github.com/.extraheader=Authorization: Basic <gh>"`。
- 凭据来源 `D:\data\work\token for Release.txt`：第 4 行 `ghp_` 是 GitHub PAT（对该仓库 `admin/maintain/push=true`），第 2 个 `Token:` 行是 CNB issues 令牌（含 `repo-code:rw`；第 1 个 Release 令牌缺该 scope，push 会 403）。凭据绝不写入 `.git/config` 或提交。
