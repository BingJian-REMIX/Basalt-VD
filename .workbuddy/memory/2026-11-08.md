# 2026-11-08（第二轮）— 深度清理 / 新建空白 VHDX / 递归提取

## 关键决策（有硬冲突，别默默改）
- **删除能力不是三引擎都有**：VHD 挂载后有真实可写路径；VMDK 以 `FileAccess.Read` 打开、容器是 7z 只读列举，写回会破坏原始镜像。→ `CleanupService.CanDelete` 仅 `VhdDiskService { MountedReadOnly: false }` 为 true；其余只扫描统计并禁用删除按钮。
- 清理目标是 Windows 系统目录，防误杀：目标必须位于所属盘符根之下、跳过 `ReparsePoint`、逐文件捕获 `UnauthorizedAccessException`/`IOException`、删前二次确认，且只删内容保留目录本身。

## 架构增量
- `Services/CleanupService.cs`：三引擎通用扫描（`$Recycle.Bin`、`Windows\Temp`、`Windows\SoftwareDistribution\Download`），`Walk` 递归统计且每层单独 catch；`DeleteTargets` 走真实文件系统，自底向上删空子目录。`CleanupWindow` 后台 `Task.Run` 扫描 + 结果列表 + 一键清理。
- `Services/EmptyVhdxService.cs`：`Disk.InitializeDynamic` → `BiosPartitionTable` 或 **`GuidPartitionTable`**（类名不是 GptPartitionTable）→ `CreateAligned(WellKnownPartitionType.WindowsNtfs, true, 1MB)` → `NtfsFileSystem.Format(volume, label)`。卷标上限 32 字符，容量 1–2048 GB。`Inspect` 用 `disk.Partitions[0] is GuidPartitionInfo` 判 GPT。
- `Services/RecursiveExtractor.cs`：`GetDirectories/GetFiles` 递归遍历 → `Directory.CreateDirectory` 重建 → `IVirtualDisk.OpenRead` 流 `CopyTo` 写入；含 zip-slip 防护（`..`/绝对路径/非法字符 + `ResolveSafe` 越界校验）、取消与节流进度上报。

## 第四轮：文本预览二进制嗅探（防满屏乱码）
- `PreviewDispatcher` Text 分支改为「先嗅探再分发」：`ReadHead(s, 100)` → `IsBinary` → 二进制直接 `new HexViewerWindow(name, ReadHead(s, 4096, sniff))`，状态栏标明「检测到二进制内容，自动降级」；文本才 `ReadText(s, sniff)` 走原 BOM/UTF-8→GB18030 链路。
- `IsBinary` 规则：任一 `\0` 立即判二进制；控制字符 `<0x20`（排除 `\t \n \r`）与 `0x7F` 占比 ≥10% 判二进制；空内容判文本；**UTF-16 LE/BE BOM 白名单**（否则既有 UTF-16 解码会被误杀）。高位字节（中文 UTF-8/GBK）不计入控制字符，避免误判。
- `ReadText(Stream, byte[]? prefix = null)` / `ReadHead(Stream, int, byte[]? prefix = null)`：把嗅探已消耗的文件头拼回结果开头。三引擎的 `OpenRead` 流不保证可 Seek，也没有重新打开流（容器引擎重开会再启一次 7z）。BOM 识别依赖 raw 开头，prefix 保证不丢。
- 自测夹具新增 `section.text`（PE 风格 + `\0`）、`nul.txt`、`ctrl.log`（15% 控制字符）、`utf16.txt`（BOM）；VHDX 回读文件数断言由硬编码 6 改为按夹具目录动态计数。
- 验证：`--previewtest` 45 PASS（新增 10 项：阈值上下边界、TAB/LF/CR、GBK/UTF-8/UTF-16 不误杀、真实 `Basalt.exe` PE 头、prefix 拼接、5 条分发降级/兜底断言）；Release 15 组全量回归 0 失败套件；Debug/Release 0 警告 0 错误。
