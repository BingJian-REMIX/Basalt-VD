## 真正根因：P/Invoke 常量错误（非火绒）

- VIRTUAL_DISK_ACCESS_ATTACH_RO=0x00010000 / ATTACH_RW=0x00020000 —— 初版写反
- ATTACH_VIRTUAL_DISK_FLAG_READ_ONLY=0x1（0x2 是 NO_DRIVE_LETTER）
- Version1 的参数字段是 RWDepth（非 GetInfoOnly）：RW 挂载必须 RWDepth=1，否则 Open 返回 0x57
- PE 里 diskpart 挂载成功是决定性对照 → 环境无罪
- 修复后 CreateVirtualDisk/OpenVirtualDisk/AttachVirtualDisk 全 0x0

## 续：修复拆分 VMDK 挂载 + VHD 无盘符诊断

**问题1（VHD 无盘符）**：原报"提示已挂载，但没有新盘符"。诊断结论：测试用 `microdos.vhd` 是空磁盘
（4MB、GPT 头有效但分区条目全零、无任何 NTFS/FAT 签名），无卷可分配盘符 —— 非代码 bug。
代码改进：MountService 改为通过 Windows Storage CIM API 主动联机磁盘 + `SetDriveLetter` 分配盘符
（比旧的 DriveInfo 轮询更可靠）；清理了临时 DebugLog(basalt_dl.txt) 诊断代码；空盘/无分区时给出更清晰的错误提示。

**问题2（拆分 VMDK 挂载失败）**：根因是 DiscUtils 0.16.13 的 `Disk.OpenDisk(path,...)` 对 VMDK 路径打开
直接返回 null（single-stream 构造仅支持单体盘），拆分描述符+sNNN 分片无法解析。
修复：将 DiscUtils.* 0.16.13 全部替换为 **LTRData.DiscUtils.* 1.0.47**（命名空间仍为 DiscUtils，支持 split/sparse）。
VmdkDiskService 静态构造里显式注册提供器：
`DiscUtils.Setup.SetupHelper.RegisterAssembly(...)` 对 Core/Vmdk/Fat/Ntfs 四个程序集。
另修复 LTRData 的 FAT 库缺陷：`FileSystemInfo.Open(stream)` 传 null 参数时 `FatFileSystemOptions` 会 NRE，
改为 `info.Open(stream, new FileSystemParameters())`（NTFS 也兼容）。

**验证**：
- `E:\VSstopmashanhi\win11\Windows 11 x64.vmdk`（twoGbMaxExtentSparse，26 分片）→ 5 分区，4 个可读 FS
  （FAT32 EFI + 3×NTFS），成功列出 Program Files / Users / Windows 及用户数据（.minecraft、jpg/png/jar/docx 等）。
- `E:\VSstopmashanhi\Ubuntu\Ubuntu.vmdk`（6 分片）→ 打开成功 2 分区，但 ext4(Linux) 不被 DiscUtils 支持，属已知限制。
- 单体 VMDK / FAT32 也验证通过。

**注意**：VMDK 被 VMware 或防病毒(Defender 扫描大文件)独占时会报 "file used by another process"，需确保 VM 关机/无锁。
Basalt 需以管理员身份运行才能挂载 VHD。

## 续2：Ubuntu(ext4) 不再抛错 + 清理陈旧 DLL

用户现象：打开 Ubuntu.vmdk 报"VMDK 中未找到可识别的分区/文件系统"；另一张 Win11 截图列表为空。
澄清：
- **Ubuntu 解析不了的真正原因**：拆分格式已能正常打开（2 分区：BIOS Boot + Linux Data），但其文件系统是 **ext4/Linux**，DiscUtils/LTRData 这个 .NET 库根本不支持读 ext 家族，所以没有"可识别的文件系统"。这跟拆分无关。
- **Win11 截图空列表**：多半是跑到了 Release 下残留的旧 `bin/Release/net10.0-windows/win-x64`（里面是 0.16.13 旧 DLL，没 LTRData，path-open 返回 null → 不报错但读不到内容）。

代码改动：
- VmdkDiskService：不再因"全部分区都无可读 FS"而整体抛 `InvalidDataException`；仅当 `_partitions.Count==0`（真·空盘）才报错。
  新增 `UnsupportedPartitionCount` / `UnsupportedNote`，`GetDirectories("")` 把不可读分区也列出，标注"（Linux Data — 暂不支持读取）"，
  这样用户能看到分区结构并理解为什么读不出文件，而不是一片空白或 cryptic 报错。
- MainViewModel.Mount：VMDK 挂载后若有不可读分区，状态栏追加"⚠ N 个分区因文件系统不受支持（如 ext4/Linux）无法读取…"。

ext4 真正可读的可行路线（未做）：把 VMDK 用 qemu-img 转 VHDX 后 `wsl --mount --vhd ... -p 1` 让 WSL 的 Linux 读 ext4；或 guestfish/libguestfs。本机当前无 qemu-img/guestfish，WSL 也未安装发行版。如需"在 Basalt 里直接读 Ubuntu 文件"，可加一个 WSL/外部工具回退方案。

## 续3：修 UI 不刷新 + 点不进目录

用户现象（截图）：① 挂载后左侧目录树空白，**必须调整窗口大小**才显示；② 显示出来后**点不进去**。

**根因（数据层，非渲染层）**：`MainViewModel.Roots`、`FolderNode.Children`、`MainViewModel.Files` 都是普通 `List<T>`。
`List<T>` 不实现 `INotifyCollectionChanged`，`Roots.Add(root)` / `Children.Add(...)` 不会通知 TreeView，
TreeView 只能等下一次布局（调整窗口大小）才被动重排 → "要 resize 才显示"。
"点不进去"则是右侧列表的目录项根本没有双击进入的处理。

**修法**：
- 新增 `Common/RangeObservableCollection.cs`：ObservableCollection 子类，批量替换时抑制中间事件、最后只发一次 Reset。
  兼顾"通知即时"与"几千个文件不卡 UI"。
- `Roots` / `Files` / `FolderNode.Children` 全部改用它；`LoadDirectory` 改为整体 `Files.Reset(items)`（去掉原来靠
  `OnChanged(nameof(Files))` 强制刷新的 hack）。
- `FolderNode` 抽出 `LoadChildren()`，`IsExpanded` setter 与"被选中"两处都调用（兜底：某些情况 TreeViewItem
  不会把展开状态写回 TwoWay 绑定源，若只依赖 IsExpanded 会出现"有展开箭头但子树为空"）。
- 右侧列表加双击进入（`FileList_MouseDoubleClick`，用 `VisualTreeHelper` 回溯到 ListViewItem 取 DataContext，
  不依赖选中时序）+ Enter 键进入（`FileList_KeyDown`）。
- `MainViewModel.Mount` 拆出 `MountPath(string)` 供无界面自测复用；`SelectedFile` setter 加
  `CommandManager.InvalidateRequerySuggested()`（否则"提取到本地"按钮的 CanExecute 不刷新）。

**新增自测模式**（都写 UTF-8 报告到 %TEMP%，避免中文乱码）：
- `Basalt.exe --uitest <路径>`：驱动 ViewModel，统计 Roots/Files 的 CollectionChanged 次数 + 模拟点击/双击。
- `Basalt.exe --rendertest <路径>`：**真实 Show() 窗口并遍历视觉树**，统计 TreeViewItem/ListViewItem 容器数，
  证明"不 resize 也已渲染"。仅 Measure/Arrange 不足以触发容器生成，必须 Show + UpdateLayout。
- `App.Headless` 静态标志：无界面模式下禁止弹 MessageBox（会阻塞甚至抛异常导致报告写不出）。
- 顺带修：`WriteReport` 统一用 UTF-8（原先默认编码导致中文乱码）；`--diag`/`--selftest` 也走同一入口。

**实测结果**：Win11 拆分盘 → TreeView 生成 6 个容器（根+5 分区）、ListView 5 项，不 resize 即显示；
点树节点后右侧正确列出分区；双击 EFI 进到 `0\EFI` 并列出 Boot/Microsoft。Ubuntu → 2 分区（均为 ext4/BIOS Boot，标注"暂不支持读取"）。
